# Описание процесса разработки

## Правила оформления задачи и Pull Request

1.  Задачи берутся из системы отслеживания задач: [https://task-tracker.yougile.com](https://task-tracker.yougile.com).
2.  Перед началом работы над задачей необходимо перевести её статус в **«В работе»**.
3.  Обновить локальную ветку `dev`, подтянув последние изменения из удаленного репозитория.
4.  Создать новую ветку, отколовшись от актуальной ветки `dev`.
    - **Формат названия ветки:** `<тип>-<ID задачи>`.
    - **Пример:** `feat-FRO-3`, `fix-BAC-123`.
5.  После завершения работы над задачей необходимо создать Pull Request на слияние вашей ветки в `dev`.
6.  **Оформление Pull Request:**
    - В Pull Request обязательно добавить участника команды для код-ревью.
    - Установить галочку **«Delete source branch when merge request is accepted»** для автоматического удаления ветки после успешного слияния
7.  Перевести задачи в статус **«Выполнено»**

### Правила оформления коммитов

Используется стандартный формат для сообщений коммитов:

<тип коммита>(<ID задачи>): <комментарий>

**Примеры:**

- `feat(FRO-3): добавить компонент корзины`
- `fix(BAC-123): исправить ошибку валидации формы`

**Основные типы коммитов:**

- `feat` — новая функциональность.
- `fix` — исправление ошибки.
- `docs` — изменения в документации.
- `style` — правки форматирования (точка с запятой, пробелы), не меняющие код.
- `refactor` — изменения кода, которые не исправляют ошибки и не добавляют новую функциональность.
- `test` — добавление или исправление тестов.
- `hotfix` — быстрый фикс
